Pathways

Rhapsody color-codes distinct paths so a user always knows which one they are on. Give each path or journey its own color and carry it as a wayfinding cue across every surface, so the color itself signals the path. This is a foundation for theming any set of parallel journeys, not a one-off section accent.

The directive

Assign each path a color and hold it end to end, across a page, a deck, a nav branch, a whole journey. Carry it as the cue wherever a surface belongs to the path: the module accent line, the eyebrow, diagrams, and section accents. Buttons stay Rhapsody Blue, and a path color is never a filled ground that has to carry text. Default to blue when a surface is neutral or spans paths.

Assign each path a color from the fixed color order (blue, teal, purple, orange, light blue, navy) — defined in Color palette → Color order & pathways — and hold it across the whole journey, adding a color only when a genuine new path exists.

Where the cue appears

  • Website and navigation. Path landing pages and their sections carry the path color in their accents (accent lines, diagrams, eyebrows on navy), so moving into a branch is visible at a glance.
  • Module accent line. Takes the path color (see Layout and spacing for the device spec).
  • Eyebrows and links. On navy, kickers, text links, and the CTA arrow may take the path color. On light grounds, links and the CTA arrow stay Rhapsody Blue, and a light path color like teal moves to the accent line or teal tick (see Color → Teal in small applications). Feature icons stay in the blue family (navy, Rhapsody blue, light blue), never the path color.
  • Content and diagrams. Path-specific decks, one-pagers, and diagrams carry the color consistently end to end.

Example: Build and Automate

The clearest current application is the two Rhapsody pillars, the first two colors in the order: Build the infrastructure is Rhapsody Blue, Automate the work is Teal — each held across its whole journey, on the website, in path-specific content, and in section accents.

Do
  • Give each path one color and hold it across its full journey, page, deck, and nav branch.
  • Default to blue for neutral surfaces or ones that span paths.
  • Add colors in the fixed order only when a genuine new path exists.
  • In the pillar example, keep Build blue and Automate teal wherever the two appear together.
Don’t
  • Swap or mix path colors, or switch a path’s color mid-journey.
  • Set teal, or any light path color, as small copy on white; the cue is the line or fill.
  • Invent a new color for a path, or reorder the sequence.
  • Theme a neutral, cross-path surface to one path’s color.
