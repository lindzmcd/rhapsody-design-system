Pathways

Rhapsody color-codes distinct paths so a user always knows which one they are on. Give each path or journey its own color and carry it as a wayfinding cue across every surface, so the color itself signals the path. This is a foundation for theming any set of parallel journeys, not a one-off section accent.

The directive

Assign each path a color and hold it end to end, across a page, a deck, a nav branch, a whole journey. Carry it as the cue wherever a surface belongs to the path: the module accent line, the eyebrow, in-context links and buttons, diagrams, and section theming. Default to blue when a surface is neutral or spans paths.

How to assign path colors

  • One color per path, held across its journey. A path reads the same color everywhere it appears, page, deck, and nav branch, so the cue stays predictable.
  • Assign in a fixed order so coding stays consistent as paths are added: blue → teal → purple → orange → light blue → navy.
  • Default to blue for neutral surfaces, or ones that span more than one path.

Where the cue appears

  • Website and navigation. Path landing pages and their sections theme to the path color, so moving into a branch is visible at a glance.
  • Module accent line. Takes the path color (see Layout and spacing for the device spec).
  • Eyebrows and links. In-context kickers, text links, and the CTA arrow take the path color. Feature icons stay in the blue family (navy, Rhapsody blue, light blue), never the path color, so the cue is carried by the accent line, eyebrow, and links, not the icons. On white, a light path color like teal drops to the line only; keep teal copy off white (see Color, Text on teal).
  • Content and diagrams. Path-specific decks, one-pagers, and diagrams carry the color consistently end to end.

Example: Build and Automate

The clearest current application is the two Rhapsody pillars, the first two colors in the sequence. Build the infrastructure is Rhapsody Blue; Automate the work is Teal. It shows the system in practice: each pillar holds its color across its whole journey, on the website, in path-specific content, and in section theming.

Do
  • Give each path one color and hold it across its full journey, page, deck, and nav branch.
  • Default to blue for neutral surfaces or ones that span paths.
  • Add colors in the fixed order only when a genuine new path exists.
  • In the pillar example, keep Build blue and Automate teal wherever the two appear together.
Don’t
  • Swap or mix path colors, or switch a path’s color mid-journey.
  • Set teal, or any light path color, as small copy on white; the cue is the line or fill.
  • Invent a new color for a path, or reorder the sequence.
  • Theme a neutral, cross-path surface to one path’s color.
