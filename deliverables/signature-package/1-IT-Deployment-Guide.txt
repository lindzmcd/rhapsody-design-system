RHAPSODY EMAIL SIGNATURE — IT DEPLOYMENT GUIDE
================================================================
Goal: every employee sends email with one consistent, on-brand
signature, pre-set at onboarding and, where possible, enforced
across the whole system.

WHAT'S IN THIS PACKAGE
  signature-standard.html ............ default signature (everyone)
  signature-with-certifications.html . adds a compliance-badge row
                                       (required roles only)
  logos/ ............................. Rhapsody logo files (host these)
  2-Employee-Setup-Guide.txt ......... hand this to staff who set their
                                       own signature

------------------------------------------------------------------
STEP 1 — HOST THE LOGO
------------------------------------------------------------------
Email clients can't read local files, so the wordmark must live at a
stable, public HTTPS URL.
  - Upload logos/Rhapsody_logo_primary.png to your CDN / web host / the
    signature tool's asset library.
  - Copy its URL and replace LOGO_URL_HERE in the template(s).
  - Keep the image at 132px wide (264px asset for retina is ideal).
Do not hotlink from SharePoint/Drive share links; use a true public URL.

------------------------------------------------------------------
STEP 2 — CHOOSE A DEPLOYMENT METHOD
------------------------------------------------------------------
A) CENTRALIZED SIGNATURE MANAGER  (recommended, truly org-wide)
   Tools: Exclaimer, CodeTwo, or similar for Microsoft 365 / Google.
   - Paste the HTML template into a new signature.
   - Map the [bracketed] fields to directory attributes (see Step 3) so
     each signature auto-fills from the directory and updates when a
     title or number changes.
   - Apply server-side to all outbound mail. This is the most reliable
     way to guarantee consistency and keep it current.

B) MICROSOFT 365 / EXCHANGE (without a dedicated tool)
   - Outlook (new) & OWA: set an org signature via Exchange admin, or
     push a default signature with Group Policy / Intune using the HTML.
   - Exchange "disclaimer" transport rules can append the block, but they
     append to every mail (including replies) and can't pull rich
     per-user fields well, so a signature manager (A) is preferred.

C) GOOGLE WORKSPACE
   - Admin console > Apps > Gmail > "Append footer" for a basic org-wide
     footer, OR use the Gmail API / a signature tool to set a per-user
     signature from directory data.

D) PER-USER AT ONBOARDING (fallback)
   - During provisioning, set the employee's default signature in Outlook
     and Gmail from the template with their details filled in (script,
     profile, or MDM). Give new hires the Employee Setup Guide as backup.

------------------------------------------------------------------
STEP 3 — FIELD MAPPING
------------------------------------------------------------------
  [First Last]          -> displayName / full name
  [Job Title]           -> title / jobTitle
  [+1 555 000 0000]     -> telephoneNumber / mobile
  [name@rhapsody.health]-> mail (used for both the text and mailto:)
  Website link is fixed: https://rhapsody.health

------------------------------------------------------------------
STEP 4 — CERTIFICATIONS (required roles only)
------------------------------------------------------------------
Use signature-with-certifications.html for roles that must display
compliance marks (e.g., Cyber Essentials Plus, ISO 27001).
  - Get the OFFICIAL issued badge artwork from Security / Compliance.
    Do not recreate, redraw, or recolor a certification mark.
  - Host each badge (transparent background) like the logo and replace
    CERT1_URL_HERE / CERT2_URL_HERE.
  - The current badges are STACKED (vertical) lockups; size each to a
    consistent 44px tall with even spacing. Add or remove <img> cells to
    match the role's actual certifications.

------------------------------------------------------------------
BRAND RULES (do not change)
------------------------------------------------------------------
  - Logo: primary wordmark only (navy bar, blue letters). Never stretch,
    recolor, or drop a glow behind it. In very tight tools the R monogram
    (logos/Rhapsody_monogram_blue-navy.png) may stand in.
  - Divider: the thin teal rule between logo and text.
  - Fonts: Poppins where supported, Arial fallback (already set).
  - Text colors: navy (#0B2C47), gray (#7E858C), Rhapsody Blue (#1A81F4)
    on a white background. No background colors, images behind text,
    quotes, banners, or social icons.
  - Company name is always "Rhapsody," never "Rhapsody Health."

------------------------------------------------------------------
STEP 5 — TEST BEFORE ROLLING OUT
------------------------------------------------------------------
Send a test to, and confirm rendering in: Outlook (Windows desktop +
web), Gmail (web + mobile app), and Apple Mail. Turn images OFF and
confirm the alt text ("Rhapsody") still identifies the sender and the
contact details still read (they are live text, not an image).
